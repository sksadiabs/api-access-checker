API Access Checker

Checks whether an API blocks the users who shouldn't reach certain data. It only reads data (GET requests). Only test systems you are authorized to test.

How it works

1. TargetEnter the address of the API you're testing.
2. UsersAdd the users to test, with their login token. Leave the token empty for "not logged in."
3. EndpointsList the URLs to test. For each user, pick whether they should be allowed or blocked.
4. RunRead the results. A FINDING means a user got data they should have been blocked from.
Fills in the form with the practice server's settings so you can try it right away.

1. Target

The address where the API is running. For the practice server, that's http://localhost:8000.

I am authorized in writing to test this address. Required for any address other than localhost.

2. Users

Each user is one role you want to test. Paste the login token for each one (from the API's login response). Leave the token empty to test as "not logged in."

3. Endpoints

Each row is one URL. Pick for each user whether they should be allowed to use it, should be blocked, or leave it on Don't test. Paths start with / and are added to the API address above, like /api/profile.

4. Run

Sends each test one at a time. It can take a few seconds.
